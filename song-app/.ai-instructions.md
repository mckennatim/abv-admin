## Code Style Requirements

### Use Modern JavaScript (ES6+) Syntax
- **Template literals** instead of string concatenation: Use `` `Hello ${name}` `` not `'Hello ' + name`
- **Arrow functions** for concise function expressions: `const fn = () => {}` not `function fn() {}`
- **const/let/var** Use `var` for exammple jupyter code
- **Destructuring** for object/array access: `const {name, age} = person` not `const name = person.name`
- **Default parameters**: `function greet(name = 'World')` not manual undefined checks
- **Array methods** over loops: Use `.map()`, `.filter()`, `.reduce()` instead of for loops when appropriate
- **Object shorthand**: `{name, age}` instead of `{name: name, age: age}`
- **Async/await** over Promises chains when possible

### variable names in Jupyter Notebooks
- use `var` instead of `const` or `let`

### Function Patterns for Jupyter Notebooks
- Use **Named IIFE** for reusable code blocks: `(function processData() { /* code */ })()`
- Use **Arrow IIFE** for quick tests: `(() => { /* code */ })()`
- Avoid variable conflicts by using function scope or unique naming

### Error Handling
- Use try/catch blocks appropriately
- Prefer optional chaining (`?.`) when checking nested properties
- Use nullish coalescing (`??`) for default values

### Comments and Documentation
- Use JSDoc comments for function documentation
- Explain complex regex patterns and algorithms
- Include usage examples in comments

## Examples of Preferred Patterns

```javascript
// ✅ Good - Modern syntax
const extractResourcePaths = (markdown) => {
    const regex = /\]\(resources\/([^)]+)\)/g;
    return [...markdown.matchAll(regex)]
        .map(([, path]) => path)
        .filter(path => path.includes('/'))
        .map(path => `resources/${path.split('/').slice(0, -1).join('/')}/`);
};

// ❌ Avoid - Old syntax
function extractResourcePaths(markdown) {
    var regex = /\]\(resources\/([^)]+)\)/g;
    var results = [];
    var match;
    while ((match = regex.exec(markdown)) !== null) {
        var path = match[1];
        if (path.indexOf('/') !== -1) {
            var parts = path.split('/');
            parts.pop();
            results.push('resources/' + parts.join('/') + '/');
        }
    }
    return results;
}
```

### When to Break These Rules
- Quick experiments and prototyping (var is fine for speed)
- Jupyter notebook exploration (use whatever works fastest)
- Legacy browser support requirements (specify if needed)
- Performance-critical code where modern syntax has overhead
- Interfacing with old libraries that expect specific patterns
- User explicitly requests older syntax for learning purposes
- Working with existing codebase that uses older patterns
